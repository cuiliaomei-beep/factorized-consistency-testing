### Building the benchmark locally

After both directories are placed under the local `plan/`:

```
python scripts\build_benchmark.py --old reports_gh_cpu_2.10 --old-version "2.10.0+cpu (Kaggle CPU)" --new reports_gh_cpu_2.14 --new-version "2.14.0+cpu (Kaggle CPU)" --verified --fix-status
```

It rewrites `benchmark/historical_bugs.json`: entries with `Kind: fixed` are marked `Verified: true` (same device), and the fix commits are filled in via the GitHub API (without a token, 60 requests per hour; 26 entries take about 1.5 hours; `--fix-status` can be dropped to get results first).

### Notes

- Installing torch with pip requires Internet On; the 2.10 CPU wheel is about 200 MB, the 2.14 one about 250 MB.
- If pip reports a conflict with the preinstalled torchvision, add `--no-deps` and ignore it; the campaign does not use torchvision.
- It does not matter if the two runs are not on the same day, as long as the machine type is the same (Kaggle CPU instance); the top of `SUMMARY.md` records the `torch` version and device, which is written into the provenance when building the benchmark.
